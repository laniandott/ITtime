UI Review · ITtime / apps/web

不是「配色变丑了」，
是样式层和结构层脱钩了

这份评审基于对 9 个页面、明暗两套主题、桌面与移动两个断点的实机截图与源码对照。结论是：视觉问题只是表象，真正让 web 端「越改越丑」的是三件事——设计 token 失效、颜色被当装饰、布局靠结构选择器打补丁。

01诊断：三个根因

先说结论。你的审美没有退步，问题在于代码里没有「唯一的视觉真相」，所以每加一个功能就多一套局部规则，最后整体失控。

根因一：设计 token 名存实亡

tailwind.config 里只定义了 brand 一个色阶，其余全部靠「现场发挥」。于是同一层级的卡片在不同页面拿到不同的圆角、阴影和字号：

维度实际在用的取值问题
圆角rounded-lg(137) · rounded-full(87) · rounded-xl(68) · rounded-md(36) · rounded-2xl(18)卡片有的 8px、有的 12px、有的 16px，挨在一起就像不同产品
阴影sm(20) · xl(12) · md(5) · lg(2) · 2xl · inner · xs阴影不表达层级，只表达「谁先写的」
字号xs(295) · sm(290) · 10px(53) · 11px(20) · 9px(13) · 8px(1)87 处小于 12px，实际渲染在 Windows 上就是「糊成一片的灰字」
主色teal #0f766e（9 次） vs 紫 #6d5efc（31 次）两个主色在抢主导权，读者无法判断「品牌色是哪个」
这不是风格问题，是可维护性问题。当一个新页面要写「卡片」时，作者必须在 5 个圆角、8 个阴影里选一个——他一定会选错，因为他没有依据。

根因二：颜色被当装饰，而不是信息编码

现在标签色同时出现在三个位置：文字颜色 + 1px 边框 + 12% 透明底色，再加上分类面板的「彩色边框 + 彩色底色」。结果是 12 个标签 = 12 个高饱和色块互相竞争，视觉上没有任何焦点。

更关键的是颜色语义在互相打架：

  • 日历里红色 = 周末，但红色在按钮上又是「删除/危险」，用户读到的是警报而不是休息日。
  • 习惯页进度条是纯绿 #22c55e（浏览器默认 accent），统计页进度条是 teal，待办页目标条又是另一种绿——同一个「进度」有 3 套颜色。
  • 日记页的「随手记」是紫色，与全站 teal 无关，因为编辑器模块用了 #6d5efc 并渗透到了外层 UI。

根因三：布局靠结构选择器反向覆盖 JSX

index.css 里有一批这样的规则——用 nth-child、:last-child、> .space-y-4 > :first-child 去「够」到 JSX 里的元素改样式：

/* index.css:92-94 —— 靠 DOM 结构定位第 2 个 section 的最后一层 div */
.tags-page .grid.items-start > section:nth-child(2) > div:last-child {
  display: grid; grid-template-columns: repeat(2, minmax(0, 1fr));
}
.tags-page .grid.items-start > section:nth-child(2) > div:last-child > div > div:first-child { min-width: 0 }

/* index.css:82 —— 靠 class 组合定位待办卡片的表头 */
.todo-page > section.page-card > .flex.items-center.justify-between { position: sticky; ... }

/* index.css:40 —— 本次最严重的视觉故障就来自这一行 */
.page-header > :last-child { margin-left: auto; }

这种写法有两个必然后果：一是改 JSX 就崩样式，所以大家不敢动结构，只能继续叠补丁；二是补丁之间互相冲突，同一个元素被 3 条规则抢，最终呈现取决于书写顺序。这就是「越改越丑」的机制——不是越改越差，是每次改动都在给上一个人擦屁股，而擦屁股的成本越来越高。

02P0 故障：可以今天就修

下面 4 个是「确定是 bug、不是审美分歧」的问题。它们每天在用户面前出现，而且修复成本极低。

✅ 已于 2026-10-17 全部修复并验证（外加 1 个登录后不刷新的功能 bug）。改动清单与修复后截图见文末「附录 A」。

① 没有操作按钮的页面，标题被推到最右边

PageHeader 里 {actions && ...} 是条件渲染，没有 actions 时 header 只剩一个子元素；而 index.css 有一条 .page-header > :last-child { margin-left:auto }，于是这唯一的子元素（标题块）被推到了最右。

打卡 / 标签 / 日记 —— 没有 actions，标题被推到最右

待办 —— 有 actions，标题正常靠左

同一套组件，两种对齐。用户看到的是「打卡页的标题跑到右上角去了」，这是最伤专业感的一类错误——它让人觉得产品没做完。

/* index.css:40 */
- .page-header > :last-child { margin-left: auto; }
+ .page-header-actions { margin-left: auto; }

/* PageHeader.tsx —— 让 actions 容器始终存在，避免结构抖动 */
- {actions && <div className="page-header-actions flex flex-wrap items-center gap-2">{actions}</div>}
+ <div className="page-header-actions flex flex-wrap items-center gap-2">{actions}</div>

② 标签列表在窄容器里「逐字竖排」

标签行是 flex items-center justify-between，左侧信息组和右侧操作组都没有 shrink-0 / whitespace-nowrap，也没有 min-w-0。中文可以在任意字符间断行，于是列宽一紧（设置页内嵌时只有 370px），就变成这样：

/* TagsPage.tsx —— 三处关键修改 */
- <div className="flex items-center justify-between rounded-lg border px-4 py-2.5">
+ <div className="flex items-center justify-between gap-3 rounded-lg border px-4 py-2.5">

// 左侧信息组：允许压缩，但名字不许断行
- <div className="flex items-center gap-3">
+ <div className="flex min-w-0 flex-1 items-center gap-3">
-   <span className="font-medium">{tag.name}</span>
+   <span className="truncate whitespace-nowrap font-medium">{tag.name}</span>
-   <span className="text-xs text-gray-400">上级：{...}</span>
+   <span className="hidden shrink-0 whitespace-nowrap text-xs text-gray-400 sm:inline">上级：{...}</span>

// 右侧操作组：永不被压缩
- <div className="flex items-center gap-2">
+ <div className="flex shrink-0 items-center gap-2 whitespace-nowrap">

顺带一个结构建议：设置页不该内嵌整个标签管理器。要么给一个「去标签页管理」的跳转，要么把标签管理做成独立路由 + 设置里只留入口。现在等于两处代码两处维护，而且窄容器必然复现这个 bug。

③ 日历页有两个标题、两套月份导航

页面级工具栏里已经有一组「‹ 今天 2026年10月 ›」，日历卡片内部又有一组「‹ 2026 年 10 月 ›」。同一屏里两个功能相同的控件，用户不知道该点哪个，视觉上也是重复噪音。

  • 删掉卡片内的 header，月份标题并入页面工具栏，只保留一套导航。
  • 日期格子里的 5 个圆点，改成一条 3px 的彩色进度条（按时长占比分段），或者干脆只在有记录的日子显示一个 4px 圆点 + 右上角时长。
  • 周末不要用红色数字，用浅灰底或加粗区分即可；红色留给危险操作。
  • 选中日不要整格填充主色（文字对比度会崩），改为1.5px 主色描边 + 浅主色底。

④ 待办右侧操作列被挤成三行

行尾的「计时 / 编辑 / ×」在一个很窄的列里各自换行，形成了三行小字竖排。原因同上：操作组没有 shrink-0，且用 text-sm 的文字按钮而非图标按钮。

建议改成图标按钮 + hover 显示：默认只显示一个「▶ 计时」，鼠标进入行才浮现「编辑 / 删除」图标。行高回到 44–48px，一屏能看到 12 条以上。

顺手发现一个功能性 UX bug（不属于视觉）：首次登录成功后页面不刷新数据，需要手动刷新一次才出现内容。原因是 loadAll() 只在 App 挂载时执行一次，而登录成功时 App 没有重新挂载。建议在 AuthGate 切到 app 模式后触发一次 loadAll()。

03设计系统：把「唯一真相」写进代码

这是让「越改越丑」停下来的关键一步。不是重画界面，而是先定义清楚：只有 1 个主色、3 档圆角、2 档阴影、5 档字号。之后所有页面都必须从这套里取。

「三色法则」——标签色只允许出现在一个位置。
现在每个标签按钮同时用了「彩色文字 + 彩色边框 + 彩色底」，三处叠加就是噪音。新规则：标签色只作为一个 5px 色点出现（时间线里则是 3px 左侧色条），文字、边框、底色一律中性。只有在「正在运行」这一种状态下，才允许整块上主色浅底。

3.2 形状：3 档圆角、2 档阴影

// tailwind.config.js
borderRadius: {
  card: '10px',   // 卡片、面板、弹窗
  ctl:  '8px',    // 按钮、输入框、下拉、标签块
  // 胶囊一律用 rounded-full，不再有 xl / 2xl / md
},
boxShadow: {
  card:  '0 1px 2px rgba(16,24,40,.05)',
  float: '0 6px 20px rgba(16,24,40,.08)',  // 仅弹窗 / 下拉
}

3.3 字阶：5 档，最低 12px

用途字号 / 字重色
页面标题 h122px / 650ink-900
区块标题 h215px / 640ink-900
正文 / 列表主信息13px / 500ink-900
辅助信息12px / 400ink-500
标签、kicker11px / 500（仅大写英文或极短中文）ink-400

把 9px / 10px 全部清掉。这些字号在 125% 缩放的 Windows 屏上会渲染成不可读的灰块，是「看起来粗糙」的主要来源之一。计时数字属于特例，用 46px + tabular-nums。

3.4 深色模式：用同一套 token，不要另起一套

正确做法是暗色下取消彩色底，只用「中性面 + 色点」；主色在暗色里提亮一档（#14A38B → #2DD4BF）用于文字和描边即可。

06落地路线

不要一次性重构。按这个顺序做，每一步都能独立上线、独立验收。

第 0 步半天

止血：修 4 个 P0 故障

  • page-header 对齐（1 行 CSS + 1 行 JSX）
  • 标签行竖排（3 处 flex 类名）
  • 日历删掉内层 header
  • 待办操作列改图标 + hover
第 1 步1–2 天

建 token，并且只建 token ✓ 结构选择器清零 + token 落地

  • 标签按钮 / 分类面板按「三色法则」改造

  • 统计页加趋势图；计划页折叠空列；习惯页重做进度条
  • 每改一页，用同一份截图脚本存一张「回归基线」
第 4 步持续

  • 禁止新增 #hex（除 token 文件外），禁止 <12px 字号
  • 新增卡片必须用 .card 组件类，不许现场写 border + rounded
  • 可以在 CI 里用 grep 做硬检查：#[0-9a-f]{6} 出现在 src/**/*.tsx 即失败

07一句话总结

你现在的界面不是「丑」，是每一处都在用不同的规则说话——7 种圆角、38 个色值、87 处小字、两个主色。
先把规则收敛成一套（第 1 步，两天，视觉零变化），再谈好看。反过来做，就会继续在旧补丁上叠新补丁，也就是现在这个状态。
真正让产品显得专业的从来不是配色，是一致性。
